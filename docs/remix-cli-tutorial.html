Remix CLI tutorial

Build a settings screen
with Remix CLI.

Install editable Flutter recipes, build a working screen, and make the source your own.

The sample is named Launchpad. You write its layout and callbacks. The CLI installs its theme and component recipes.

Start with an empty projectDownload both samples

Tested with Flutter 3.44.0 and Dart 3.12.0. The steps use a pinned Remix checkout.

How the pieces fit together

The CLI installs source in your application. The generator connects that source to Remix widgets.

  1. Install the recipe

    Add Button with the CLI.

    lib/ui/components/button.dart

    The recipe defines Button styles. The CLI also installs the theme.

    Your editable source

  2. Generate the adapter

    The CLI runs build_runner with mix_generator.

    lib/ui/components/button.g.dart

    The adapter exposes AcmeButton. Regenerate it after recipe API changes.

    Generated source

  3. Build the screen

    Use the installed widgets.

    lib/main.dart

    Your application supplies the layout, state, and callbacks.

    Your application code

At runtime: the adapter uses package:remix/remix.dart for rendering and interaction behavior.

GitHub CI runs repository checks separately. Step 11 explains the checks and how to test your sample.

Before you start

You need basic Flutter knowledge, Git, a terminal, and an installed Flutter SDK. The sample targets desktop browsers and uses local state. It has no backend or mobile layout.

Follow the steps to build the default sample. Step 10 covers Fortal in a separate project. The download includes both complete projects, generated adapters, and four tests per preset.

7 · Customize

Customize a Button or the theme

Choose an instance override, a recipe edit, or a theme value based on which controls should change.

One instance: the cyan preview button

Open lib/main.dart, _WorkspacePageState.build, and find the Run preview button. Its style overrides one instance.

The explicit hover and pressed fragments override those recipe states too. The neighboring Button keeps its recipe. The onPressed callback still belongs to the application.

One component family: make medium buttons taller

Open lib/ui/components/button.dart, _metricsFor. Change only the medium minHeight from 36.0 to 44.0.

Restart or reload the running application to see the change. This edit changes a recipe value. It does not change the generated widget signature.

When you change recipe parameters, enums, or annotations, regenerate the adapter.

The theme: shared values and runtime switching

Open lib/ui/theme/theme_data.dart, AcmeThemeData, for shared values. Open lib/main.dart, _SampleAppState.build, for the light and dark switch.

A new token also needs an entry in AcmeThemeData.tokens. Include its value in constructors, copyWith, equality, and hashCode.

See the customization reference for token and theme examples.

Check the result

Every medium Button in this default sample uses the 44-pixel minimum height. The cyan Button keeps its instance override. The review measured Save changes at 44 CSS pixels with device pixel ratio 1.

9 · Review updates

Keep the source you edited

Use a diff to inspect the bundled recipe without replacing your source.

current is your file. proposed is the bundled template. The removed line is your 44-pixel edit. The added line is the upstream 36-pixel value.

The diff reports the difference and leaves the project source unchanged.

Confirm that the medium minHeight still equals 44.0 in button.dart.

Optional: replace the requested recipe

Commit or copy your edit before this experiment. The command below replaces the requested Button recipe with the bundled version.

What GitHub CI adds

CI means continuous integration. GitHub runs the repository's automated checks when the PR changes.

The repository checks install both presets in fresh consumers and check source derivation, documentation, and other package contracts. These checks run outside Launchpad.

For the repository workflow, open .github/workflows/ci.yaml. For the consumer checks, open tool/check_open_code.dart and the open_code/ fixtures.

Check the result

Each sample reports no analyzer issues, passes four tests, and builds its web application. Hosted package validation remains a release step after publication.
