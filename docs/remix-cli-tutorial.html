Start here

What you will build

Build a small settings screen from editable Remix recipes.

The sample is named Launchpad. It is a fictional application used only for this tutorial. You write its screen, layout, and callbacks. The Remix CLI installs its theme and component recipes.

You will create a Flutter project, install the default preset, and render a Button. Then you will compose the screen, customize a recipe, and verify source preservation. An optional section repeats the setup with Fortal.

This tutorial assumes basic Flutter knowledge and access to a terminal. Use a desktop browser for the sample. The sample does not include a mobile layout or a backend.

7 · Customize

Change appearance at the correct level

Use a call-site override, a recipe edit, or a theme value according to the intended scope.

One instance: the cyan preview button

Open lib/main.dart, _WorkspacePageState.build, and find the Run preview button. Its style overrides one instance.

The explicit hover and pressed fragments override those recipe states too. The neighboring Button keeps its recipe. The onPressed callback still belongs to the application.

One component family: make medium buttons taller

Open lib/ui/components/button.dart, _metricsFor. Change only the medium minHeight from 36.0 to 44.0.

Restart or reload the running application to see the change. This edit changes a recipe value. It does not change the generated widget signature.

When you change recipe parameters, enums, or annotations, regenerate the adapter.

The theme: shared values and runtime switching

Open lib/ui/theme/theme_data.dart, AcmeThemeData, for shared values. Open lib/main.dart, _SampleAppState.build, for the light and dark switch.

A new token also needs an entry in AcmeThemeData.tokens. Include its value in constructors, copyWith, equality, and hashCode.

See the customization reference for token and theme examples.

Check the result

Every default medium Button uses the 44-pixel minimum height. The cyan Button keeps its instance override. The review measured Save changes at 44 CSS pixels with device pixel ratio 1.

What GitHub CI adds

CI means continuous integration. GitHub runs the repository's automated checks when the PR changes.

The repository checks install both presets in fresh consumers and check source derivation, documentation, and other package contracts. These checks run outside Launchpad.

For the repository workflow, open .github/workflows/ci.yaml. For the consumer checks, open tool/check_open_code.dart and the open_code/ fixtures.

Check the result

Each sample reports no analyzer issues, passes four tests, and builds its web application. Hosted package validation remains a release step after publication.
