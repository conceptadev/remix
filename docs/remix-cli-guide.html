Own the recipe. Remix keeps the behavior.

Remix is a Flutter component library. remix_cli copies your theme and your visual recipes into your app as readable Dart. mix_generator connects those recipes to Remix widgets, which keep interaction, focus, loading, disabled behavior, and accessibility.

This function decides appearance. RemixButton drives the interaction state and the semantics. ButtonStyler is a Mix styler: a chainable description of how one Remix widget looks in each state.

The model

Three short sections. Read these once.

What you own

Four ideas explain the whole workflow.

Open recipes

Your theme, variants, sizes, and state styles are ordinary Dart files in your repository. You read them, edit them, and review them like any other source.

Packaged behavior

Remix keeps rendering, pointer and keyboard input, focus, semantics, loading, and disabled rules. A fix there reaches you through flutter pub upgrade.

Typed seam

mix_generator writes a typed adapter between each recipe and its Remix widget. The adapter is the only file you do not edit.

Deliberate distribution

remix_cli installs source and compares source. It replaces a file you own only when you pass --overwrite.

Shadcn/ui says you own the component. Remix is more exact: you own the theme and the visual recipes, and Remix stays the behavioral component library. That is why an upstream accessibility fix still reaches your app without a copy-and-paste round.

The ownership seam

Theme and recipe, generated adapter, Remix widget. Each layer updates a different way.

Three things land in your repository: source you own, one generated adapter for each component, and a dependency on package:remix.

You own
lib/ui/theme/tokens.dart · theme_data.dartYour color and radius vocabulary, and the values behind it. Remix has no opinion about either.
You own
lib/ui/components/button.dartThe recipe. One function returns a ButtonStyler with geometry, typography, variants, and state fragments. A state fragment applies in one widget state, such as hover.
Generated
lib/ui/components/button.g.dartThe adapter. mix_generator turns the recipe into AcmeButton, with one named constructor for each variant.
Remix keeps
package:remix — RemixButtonRendering, pointer and keyboard input, focus, semantics, loading, and disabled behavior.

The adapter is the seam. Its build method calls RemixButton and passes your recipe as the style. Nothing in Remix reads your files. Nothing in your files reimplements Remix.

Each layer has one owner and one update route.

LayerOwnerHow it updates
Theme and recipeYour applicationYou edit the file.
Generated adaptermix_generatorRun build_runner.
Widget behaviorpackage:remixUpgrade remix.
Bundled recipe templateThe remix_cli registryUpgrade the CLI, then review with --diff.
How do upstream updates reach me?

Upgrade remix for behavior and accessibility fixes. Upgrade remix_cli and run remix add button --diff to read the changes to the bundled recipe. The CLI never replaces your customized source on its own.

Fortal or open code

One decision, made before you install. Both sit on the same Remix widgets.

Fortal is a Radix Themes-inspired preset theme and widget catalog, shipped as the remix_fortal package. Open code is this CLI.

FortalOpen code
Appearance lives inA package dependencySource files in your lib/
Normal customizationToken and style overridesEdit the recipe
Behavioral foundationRemixRemix
Updatesflutter pub upgradeReview source with --diff
Best fitA ready-made system you do not intend to changeA design system the application owns

One app can use both. They are Remix widgets either way, so a Fortal screen and an open-code screen can sit beside each other.

The path

Six steps, in order. Each one separates the command from the change it makes.

The six steps

The whole journey on one screen, before the detail.

Where this path starts

Every step below runs inside an existing Flutter package. remix_cli does not create the application. Run the commands from the directory that owns pubspec.yaml.

STEP 1Installdart pub global activate remix_cliThe remix command becomes available. Your app does not change. STEP 2Initializeremix init --prefix AcmeTwo files: the configuration and an empty managed barrel. STEP 3Previewremix add button --dry-runThe plan, and the proposed source. Nothing is written. STEP 4Addremix add buttonSource, dependencies, exports, and the generated adapter. STEP 5First renderAcmeButton.primary(…)Your widget tree shows the component for the first time. STEP 6Updateremix add button --diffCompare a newer template with your file, then decide.

Steps 1 to 4 are the CLI. Step 5 is your application code. Step 6 is the loop you repeat for the life of the project. Between step 5 and step 6, two sections explain where to change appearance and which states Remix drives.

1

Install the CLI

This walkthrough uses one command name all the way through: remix.

Install the exact CLI version this guide was written against. If Dart prints a PATH instruction, follow it and reopen the shell before you continue.

RESULT

The command is ready. Every command below now works exactly as written. Your Flutter app has not changed yet.

Requirements

  • Flutter 3.44 or newer. The CLI runs flutter --version --machine before it touches a file.
  • A Flutter package root. Its pubspec.yaml must list the Flutter SDK under dependencies.
  • Git on PATH, for --diff only.
Pin the CLI to the project, for a team or for CI

Use a development dependency when the CLI version must live in the project's lockfile. The registry travels with the CLI, so the lockfile then pins the bundled templates too.

In that mode every command in this guide keeps its arguments and changes its prefix. Read remix add button --diff as dart run remix_cli:remix add button --diff. Do not mix the two invocation styles inside one project.

2

Initialize

Two files, written once. They decide every name the CLI generates.

Run init from the package root. --prefix sets every generated name. --ui-path selects the directory that receives installed source; it defaults to lib/ui.

RESULT

Configuration, not UI. The command writes exactly two files: remix.yaml and an empty managed barrel at lib/ui/ui.dart. No component source exists, and nothing renders yet.

remix.yaml is the contract. prefix: Acme turns the registry item button into AcmeButton, AcmeButtonVariant, and acmeButtonStyle. ui.dart is the managed barrel: the CLI owns the lines between its marker comments and preserves everything outside them.

Advanced: rerun, repair, and prefix changes

init doubles as a repair command. It recreates the missing file and names exactly what it touched.

State on diskWhat init prints
Neither fileInitialized remix.yaml and lib/ui/ui.dart.
Barrel onlyCreated remix.yaml; preserved lib/ui/ui.dart.
Config onlyCreated lib/ui/ui.dart; preserved remix.yaml.
Both presentRemix is already initialized.

A rerun with a different --prefix or --ui-path fails. The CLI will not rename source you own. Install state is tracked by path, not by the symbols inside the file, so after a manual prefix change remix add button still finds lib/ui/components/button.dart, reports Preserved button., and keeps the old names.

The prefix must be an ASCII UpperCamel Dart identifier, and its lowercased form cannot be a reserved word. paths.ui must stay inside lib/.

3

Preview before you write

Two read-only modes. Both run preflight, then stop before any process or file change.

ModeWhat it showsWhat it writes
--dry-runItems, dependencies, files, exports, and generated targetsNothing
--diffThe proposed authored Dart source, as a real git diffNothing

--dry-run shows the plan

RESULT

A plan, not files. missing means the CLI would write the item. After a successful install the same command reports complete for both lines and still writes nothing.

--diff shows the source

--diff renders and formats the proposed files into a temporary tree, then runs a real git diff against your source. Before the first install every file is new, so the whole diff is additions. This excerpt keeps the plan lines and the first few lines of the first file.

The command reports one of three things, and the third one is the important one.

When you run itWhat it prints
Before installationEvery proposed file as an addition.
After a clean installationNo authored-source differences.
After you edit your copyA real diff. current is your file; proposed is the bundled template.
--diff covers the item you name

It includes the requested item, any missing registry dependency, and the barrel. It omits dependencies that are already installed. To review Theme on its own, run remix add theme --diff.

Both preview modes return before flutter pub get. They do not add dependencies, run generation, write source, or change what the app renders.

4

Add the component

One add installs one item. Registry dependencies arrive first.

RESULT

Source, not pixels. The CLI writes the theme, button.dart, the generated adapter, and the barrel exports. It does not place a button on a screen. Step 5 does that.

The file tree is the part worth reading. Everything below lib/ui/ now belongs to the application.

Each item reports one status word. The word tells you whether the CLI wrote your file.

Added
The file did not exist, so the CLI wrote it.
Preserved
The file already existed and was left untouched.
Updated
You passed --overwrite for that item.

A second remix add button is a successful no-op.

Special cases: dependency order, and the icons item

Every component item depends on theme. Only data_table depends on other components, because its selection column is a checkbox, its pager is a pair of icon buttons, and its page-size control is a select. One command installs all four prerequisites, in order.

icons is optional and has no generated adapter. Install it when your application wants named icon aliases. The complete 318-glyph catalog stays available through RemixIcons, and static references stay tree-shakable.

Make it yours

Three scopes. Choose the smallest one that solves the problem.

Every visual change belongs at one of three levels: one call site, one component family, or the whole theme. Each level is a different file, and each has a different blast radius.

One call site SMALLEST

The generated adapter merges its style parameter last, so a call site can override any part of the resolved recipe without forking it.

EFFECT

One button changes. No file in lib/ui/ was touched, so remix add button --diff still reports no authored-source differences.

State fragments merge by state, not by depth

An override that must beat the recipe's hover fill needs a hover fragment of its own. A bare .color(…) replaces the idle value only. That is why the snippet above declares .onHovered(…).

One component family THE RECIPE

Open lib/ui/components/button.dart. Geometry lives in one record for each size. This is the table you edit when a touch target is too small.

Raise the medium height from 36 to 44 for a touch-first application. That is the whole edit.

EFFECT

Every medium button changes. The two frames above are the same size, so the taller control is the change. Nothing else in the application moved.

There is no lockfile for installed source, so the CLI cannot merge. It can only show you the difference, and it reads from the template's point of view.

Read the direction with care. current is your file and proposed is the bundled template, so your 44.0 is the removal and the upstream 36.0 is the addition. The command reports; it never writes.

Show the rest of the recipe: variants and state fragments

Each variant is a fill, a foreground, and two state fragments. Solid variants dim their own fill on hover and further on press. Quiet variants use the accent token to make interaction visible.

The highlighted case paints the red column in the render at the top of this guide. It names AcmeTokens.destructive(), so one theme value paints every destructive button.

.primary and .horizontal(…) are contextual shorthand: they name a member of the type the parameter expects. The styler methods come from Mix, and the Styler API page lists them. The complete file is in the reference.

After you add or rename an enum value, run dart run build_runner build. The named constructors come from that enum. Commit button.g.dart, and do not edit it.

The whole theme WIDEST

Remix ships no theme. The names in tokens.dart are your vocabulary. A MixToken is only an identity; its value comes from the nearest AcmeThemeScope, which installs AcmeThemeData and a matching MixScope together.

Add a token here and to AcmeThemeData, and the scope map exposes it. Rename one, and the analyzer finds every recipe that used it. Every recipe reads its corner radius from one token, so one value turns every control into a pill.

EFFECT

Every recipe changes. No recipe changed between these two builds. The theme did.

Light and dark are the same mechanism. Switching at runtime changes only the value passed to the scope.

States

Remix decides when a state applies. Your recipe decides how it looks.

One control, six states, captured from one build of the same application.

Read the table left to right: the state, what decides that it applies, and the one line in your recipe that styles it.

StateWhat decides it appliesWhat the recipe declares
HoverPointer tracking in RemixButton.onHovered(…) fill and content color
PressedGesture handling in RemixButton.onPressed(…) fill and content color
Keyboard focusFlutter focus, in traditional highlight mode.onFocusVisible(…) outline color, width, and offset
Disabledenabled: false on the widget.onDisabled(…) opacity, and no focus ring
Loadingloading: true on the widget.spinner(…) size, color, opacity, and duration

Loading also refuses interaction, so RemixButton reports the disabled state at the same time. That is why the loading render is faded: the same .onDisabled(…) fragment applies.

The recipe never asks whether the pointer is down, and never blocks a tap while the button loads. Remix does both. That is the whole reason the behavior stays in the package.

6

Update

There is no merge. There is a deliberate review loop.

Two different things update, and they update separately.

What changedWhat you runWhat happens to your files
Remix behavior or accessibilityflutter pub upgrade remixNothing. The fix arrives inside the package.
A bundled recipe templatedart pub global activate remix_cli, then remix add button --diffNothing, until you ask for a replacement.

A new remix_cli carries a new bundled registry. If you pinned the CLI to the project, use flutter pub upgrade remix_cli for the first command. An empty diff after a CLI bump is normal: a tool-only release can leave every template unchanged.

If you want the upstream version of one recipe, take it whole.

--overwrite replaces only the item you name, and preserves installed registry dependencies. An update to Button never rewrites a customized theme.

The Remix drift notice

Each registry is authored against one remix version. A caret constraint can resolve a newer one. add reports that gap after it resolves your lockfile, and continues.

The message names both versions

“Resolved remix <the version your lockfile picked>; this remix_cli registry was authored against <the snapshot version>. Run flutter pub upgrade remix_cli, then review with --diff.”

The notice does not fail the install and does not touch your files. A resolved remix below the authored version does fail, because the registry source was never compiled against it.

A new remix can change a styler API. Your recipe then stops compiling, the compiler names the line, and add --diff shows the new template.

Show reinstall behavior for every install state
State of the itemaddadd --overwrite
Not installedInstalls it and reports AddedInstalls it and reports Added
Fully installedNo-op, and reports PreservedRe-renders and reports Updated
Partially installedError. The CLI refuses to guess.Re-renders every file and reports Updated

A partial install is an error, not a silent repair. Look with --diff, then choose --overwrite.

Removing an item

There is no remove command. Delete the item's files and its managed exports. The next add treats the item as missing.

Charts outside Fortal

remix add chart installs one editable source file with line, grouped bar, and pie charts. It adds mix_chart and no Fortal dependency. Set a positive centerRadius to turn the pie into a donut.

mix_chart keeps ownership of data, painting, gestures, transitions, tooltips, and semantics. Your local recipe owns the palette, axes, grid, geometry, and tooltip styling. It reads the same theme tokens, so it works with a theme installed before chart support existed.

The CLI sorts the exports and rewrites only the lines between the markers.

Names come from the prefix. With prefix: Acme, the button recipe produces these symbols. The generator drops a trailing Style and capitalizes the function name, so renaming the recipe renames the widget.

Dependency rules

The CLI reads your pubspec.yaml and adds only the packages you do not declare. It preserves hosted, path, Git, custom-hosted, and override declarations byte for byte. Runtime packages must stay under dependencies.

PackageRequired sectionWhy
remixdependenciesInstalled source imports it at runtime.
mix_annotationsdependenciesInstalled source imports it at runtime.
mix_chartdependenciesThe chart item imports it at runtime.
remix_ui_iconsdependenciesThe icons item imports it at runtime.
build_runnerEither sectionBuild time only.
mix_generatorEither sectionBuild time only.
Runtime packages belong in dependencies

If remix sits under dev_dependencies, remix add button stops before it writes anything. A package declared in both sections fails the same way. Move the package, then run the command again.

An incompatible constraint also fails preflight. The CLI never widens a constraint you chose.

When something fails

Three problems meet a fresh app first.

Your linter flags the generated adapters. A default Flutter app includes flutter_lints, and the current generator emits explicit this. qualifiers. Exclude generated adapters from consumer linting.

With that exclude, flutter analyze lib reports No issues found!.

Text field selection handles fail. An installed text field needs an Overlay ancestor once it takes focus. Material, Cupertino, and any routed WidgetsApp already provide one; a bare WidgetsApp(builder: …) does not.

“Run remix init before remix add.” The current directory has no remix.yaml. Run the CLI from the package that owns pubspec.yaml. In a workspace, use the member package, not the workspace root.

Use the message to choose the next command.

What you seeExitWhat to do
add requires exactly one item64Run one remix add command for each item.
modes are mutually exclusive64Choose one of --dry-run, --diff, or --overwrite.
Unknown registry item1Use a name from the catalog.
Registry dependency … is partially installed1Name that dependency, and run remix add theme --overwrite.
Requested item … is partially installed1Inspect with --diff, then use --overwrite to take the bundled source.
No error0Success, including previews and no-op reruns.
A late failure leaves authored source on disk

Generation or analysis can fail after the write. The source stays for inspection. Fix the reported problem, then run the same command again.
